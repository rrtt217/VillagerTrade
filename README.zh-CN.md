# VillagerTrade（村民交易）

[English](README.md) · **中文** · [更新日志](CHANGELOG.zh-CN.md)

为 Cuberite 提供"近似原版"村民交易的插件。Cuberite 的 Lua API 无法读取村民真实职业，
因此插件为每个村民分配一个虚拟职业、一个可持久化的标识符，以及一份会随时间刷新的交易列表。

## 功能

- **右键村民**打开交易界面（原版村民窗口：两个输入槽、一个输出槽，外加玩家背包）。
- **潜行 + 右键村民**：不打开界面，直接在聊天栏列出该村民的交易。
- **村民唯一标识符**：每个村民分配 `vt-<职业>-<随机字符>`，存放在 CustomName（随世界持久化），
  其经验与上次刷新年龄记录在 `villager_data.txt`。
- **虚拟职业** `vtFarmer` … `vtGeneric`（见 `trades.txt`）；村民只提供本职业的交易。
- **经验等级**：交易会给村民加经验，同时为玩家掉落经验球；100 / 300 / 600 经验对应等级
  1 / 2 / 3，解锁更多交易。
- **交易刷新**：世界时间每过 5 分钟，重新生成该村民的交易列表。
- **阻止命名**：命名牌无法给插件管理的村民改名。
- **村民刷怪蛋**：用 1 绿宝石 + 1 鸡蛋合成，或从 `vtGeneric` 村民处购买（合成配方有开关，
  见 `settings.ini`）。

## 安装

把 `VillagerTrade` 文件夹放进 `<服务器>/Plugins/`，重启服务器（或重载插件）。
本插件按 Cuberite 的 1.12.2 协议开发与测试，交易窗口布局与客户端原版村民窗口一致。

## 配置 —— `settings.ini`

```ini
[Features]
EnableVillagerSpawnEggCrafting=1
```

- 键名**两侧不要写空格**：Cuberite 会把空格算进键名，导致读取失败并静默使用默认值。
- 修改后需重载插件（`/reload` 或控制台 `reload`）。

## 交易界面操作

| 操作 | 效果 |
|---|---|
| 把物品放进槽 0 / 1 | 交易输入（槽 1 仅双输入交易会用到） |
| 左键输出槽（槽 2） | 完成**一次**交易 |
| Shift + 左键输出槽 | **尽量多交**；产出按最大堆叠填入背包（先叠加已有堆叠，再占用空槽） |
| 右键输出槽 | 在**当前输入可匹配的所有交易**之间循环切换 |
| Shift + 右键 槽 0–2 | 已禁用 |
| 关闭窗口 | 没用掉的输入会掉落在脚下；未付款的产出预览会被丢弃 |

输出槽由插件独占：不接受放置物品；当输入不再匹配时，未付款的预览会立即清除，无法被"白拿"。

### 输入完全相同，如何在不同交易之间切换？

`trades.txt` 中可能有多条交易匹配同一组输入（例如 `1 绿宝石` 会匹配所有 `(min,max)` 区间
允许 1 的 `emerald -> …` 条目）。输出槽始终显示**当前选中的那条**，
**右键输出槽即可切换到下一条匹配交易**。当匹配条数大于 1 时，插件会在聊天栏提示：

```
[VillagerTrade] 交易 2/4：2x emerald -> 1x whitewool
```

当匹配集合发生变化（例如你增减了输入）时，选择会重置为第一条匹配，保证每次从可预期的状态
开始。如果两条条目看起来完全相同，循环切换仍有意义：每条条目在生成交易列表时会各自随机
生成数量与附魔。

## `trades.txt` 格式

```
<输入1>, (<min>,<max>) [; <输入2>, (<min>,<max>)] = <产出>, (<min>,<max>) | <权重> | <职业> | <解锁等级> | <交易经验>
```

- 物品名使用 Cuberite 的写法（`lapislazuli`、`chainmain_leggings`——官方拼写如此），也可直接
  写数字物品 ID。
- `^damage` 设置物品损伤值（如 `spawn_egg^120`）；`-"<附魔>"` 设置附魔
  （`"id=lvl;…"` 或 `"ByXpLevels(min,max)"`）。
- `权重` 是该条目在生成交易列表时被选中的概率（0–1）。
- `职业`：0 = vtFarmer，1 = vtLibrarian，2 = vtPriest，3 = vtBlacksmith，4 = vtButcher，
  5 = vtGeneric；`解锁等级` 为 0–3。
- 无法识别的物品名会在控制台告警，而不是静默生成空物品交易。

## 数据存储

`villager_data.txt`，每个村民一行：

```
<村民ID> = <职业> | <经验1> | … | <经验6> | <上次刷新世界年龄>
```

写入时机：玩家离开时、每 5 分钟、插件卸载或服务器停止时。最后一列为 `-1` 表示"从未刷新"。

## 已知限制

- Shift + 右键没有行为（有意禁用）。
- Cuberite 的默认点击处理在拾取后可能留下数量为 0 的"幽灵物品"，插件会把这类槽视为空槽。
- 村民职业是虚拟的——Lua API 无法读取真实职业。
- 交易列表保存在内存中、按需重新生成，只有刷新年龄会被持久化。
- `player_trades.txt` / `player_trade_experience.txt` 是 v1 文件，仅为迁移保留。
